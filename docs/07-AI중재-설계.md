# 07. AI 중재 브리지 설계 (1:1 화해 브리지 v2)

> 작성일: 2026-07-20
> 배경: 사용자 제안 — "둘을 바로 같은 톡방에 넣으면 오히려 악화될 수 있다. 각자 AI와 먼저 상담하고, 준비되면 AI가 중재하는 합동방으로 모으자."

## 왜 이 구조가 맞는가

이 설계는 **전문 조정(mediation) 실무의 표준 절차와 정확히 일치한다.** 실제 갈등 조정에서는 합동 세션 전에 조정가가 각 당사자를 따로 만나는 **카우커스(caucus, 개별 면담)**를 먼저 한다. 이유는:

1. 감정이 정리되지 않은 상태의 직접 대면은 비난 → 방어 → 역비난의 악순환으로 흐르기 쉽다
2. 각자의 "진짜 욕구"(서운함의 뿌리)는 상대 앞에서가 아니라 안전한 개별 공간에서 먼저 언어화된다
3. 조정가는 양쪽 이야기를 종합한 뒤에야 공통 지점과 지뢰밭을 알고 합동 세션을 운영할 수 있다

또한 리서치 근거와도 맞물린다: 사과의 효과는 "책임 인정"이 좌우하는데([00-리서치보고서](00-리서치보고서.md) §1-3), 준비 없이 만나면 변명("나도 그럴 만했어")부터 나온다. 개별 단계에서 책임 인정 언어를 미리 준비시키는 것이 성공률을 높인다.

**결론: 채택.** 단, 아래 안전장치가 전제다.

## 전체 플로우

```
[A] 브리지 요청 ──→ [B] 수락 (내용 비공개, "대화해볼 의향" 만 확인)
        │
        ▼
  ┌─ 1단계: 개별 AI 상담 (각자, 비동기, 1~7일) ─────────────┐
  │  · 서운했던 점 / 오해라고 생각하는 점 구조화 입력          │
  │  · AI와 1:1 채팅: 감정 타당화 → 사건 정리 → 상대 관점    │
  │    조망(REACH의 E단계) → 내가 인정할 몫 찾기             │
  │  · 산출물: "합동방에서 하고 싶은 말" 워크시트             │
  └────────────────────────────────────────────────────┘
        │
        ▼
  [2단계: 준비도 게이트] — 양쪽 모두 충족해야 합동방 개설
   · 자가 체크(나는 상대 이야기를 끝까지 들을 준비가 됐다 등)
   · AI 평가: 비난 언어 비율, 책임 인정 문장 존재, 감정 강도
   · 한쪽이라도 미준비 → 개별 상담 연장 (실패 아님을 명시)
        │
        ▼
  ┌─ 3단계: AI 중재 합동방 (A + B + AI) ──────────────────┐
  │  · AI가 오프닝: 규칙 안내 + 양측 사전 동의한 요약 공유    │
  │  · 구조화 순서: 각자 이야기 → 반영적 경청 확인("들은 대로  │
  │    말해보기") → 오해 지점 정리 → 사과/인정 → 합의       │
  │  · AI는 발언권 정리, 재해석(reframing), 공통점 짚기      │
  └────────────────────────────────────────────────────┘
        │
        ▼
  [사후] 1주 후 각자 체크인 → 관계 상태 업데이트, 필요시 2차 세션
```

## 악화 방지 3단계 안전장치 (합동방)

| 단계 | 트리거 (AI 감지) | AI 행동 |
|---|---|---|
| 1. 개입 | 비난 일반화("넌 항상"), 인신공격, 과거 들추기 연쇄 | 부드러운 리프레이밍: "잠깐요, 지금 말씀은 '그때 혼자라고 느꼈다'는 뜻으로 들려요. 맞을까요?" |
| 2. 냉각 | 개입 2회 후에도 격화, 모욕적 표현 | 타임아웃 제안 + **개별 채팅으로 일시 분리** ("10분 쉬었다 올까요? 그동안 저와 잠깐 이야기해요") |
| 3. 종료 권고 | 위협·폭언, 한쪽의 반복적 이탈 의사 | 세션 종료 + "오늘은 여기까지가 최선이에요. 화해는 한 번에 되지 않아도 괜찮아요" + 개별 후속 케어. 위협 감지 시 안전 분기(전문기관 안내) |

핵심 원칙: **AI는 화해를 목표로 밀어붙이지 않는다.** "오늘 합의 실패"도 정상 결과로 처리하고, 용서 없이 각자 마음 정리로 종료하는 경로를 항상 열어둔다 (용서≠재연결 원칙, [01-아이디어](01-아이디어.md)).

## 프롬프트 엔지니어링 — 필요한가? **그렇다. 이 제품의 본체다.**

일반 챗봇 프롬프트로는 안 된다. 이유: ① 중재는 "말 잘하는 것"이 아니라 **절차**다(순서를 지켜야 함) ② 안전 분기(폭력·자해 신호)가 법적·윤리적 요구사항 ③ 두 사용자 사이에서 **중립성**을 유지해야 한다(한쪽 편들면 제품 신뢰 붕괴).

### 프롬프트 아키텍처 (역할별 시스템 프롬프트 분리)

**공통 원칙 (모든 프롬프트에 포함)**
- 근거 프레임워크 명시: REACH(공감 단계), NVC(관찰-감정-욕구-요청), 사과 6요소
- 정체성 고지: "나는 상담사가 아니라 대화를 돕는 조력자" — 임상 조언 금지
- 안전 분기: 폭력·학대·자해 언급 시 중재 중단 → 전문기관 안내 (하드코딩된 분기, 프롬프트에만 의존하지 않고 별도 분류기로 이중화)
- 출력 제약: 2~4문장, 존댓말, 판단·진단 언어 금지("당신은 회피형이네요" ✕)

**① 개별 상담 AI (1단계) — 시스템 프롬프트 골격**

```
당신은 '잇다'의 관계 회복 조력자입니다. 사용자는 {상대와의 관계}인
{별칭}과(와)의 갈등으로 화해를 준비하고 있습니다.

목표(순서대로, 한 번에 하나씩):
1. 감정 타당화 — 사용자의 서운함을 충분히 듣고 인정한다. 조언하지 않는다.
2. 사건과 해석 분리 — "무슨 일이 있었나"와 "그걸 어떻게 받아들였나"를
   나누어 정리하도록 돕는다 (NVC의 관찰/감정 분리).
3. 관점 조망 — 준비가 되었을 때만, 상대의 사정을 상상해보도록 초대한다.
   강요하지 않는다. "상대가 옳다"가 아니라 "상대에게도 이야기가 있다"까지만.
4. 내 몫 찾기 — 사용자가 인정할 수 있는 자기 몫이 있는지 스스로 발견하게
   돕는다. 없다고 하면 받아들인다.
5. 합동 대화 준비 — 하고 싶은 말을 비난 없는 문장으로 함께 다듬는다.

금지: 상대방 비난에 동조하기, 화해 재촉, 심리 진단, 3문장 초과 답변.
안전: 폭력·협박·자해 언급 시 즉시 [SAFETY] 토큰 출력 후 공감적으로 마무리.
```

**② 합동 중재 AI (3단계) — 시스템 프롬프트 골격**

```
당신은 A와 B의 화해 대화를 진행하는 중립 중재자입니다.
입력으로 양측이 공유에 동의한 개별 상담 요약을 받았습니다: {A요약} {B요약}

절차(단계를 건너뛰지 않는다):
1. 오프닝 — 규칙 3가지 안내(끝까지 듣기, 과거 들추기 대신 오늘 주제, 언제든 쉬어가기 가능)
2. A의 이야기 → B에게 "들은 내용을 자기 말로" 요약 요청 → A 확인
3. B의 이야기 → A에게 동일하게
4. 오해 지점 정리 — 양측 서사에서 같은 사건의 다른 해석을 짚어준다
5. 인정과 사과 — 각자 인정할 몫을 말할 기회를 만든다 (사과 6요소 중
   '책임 인정'을 부드럽게 유도하되 강요하지 않는다)
6. 마무리 — 합의된 것 1가지, 각자 해볼 것 1가지 확인

중립 규칙: 누가 옳은지 판정하지 않는다. 한 턴에 한 사람에게만 발언을
넘긴다. 두 사람 발언량 균형을 유지한다.
개입 규칙: "항상/절대" 일반화, 인신공격 감지 시 → 관찰 언어로 재번역해
확인 질문. 2회 이상 반복 시 → 휴식 제안 후 [COOLDOWN] 토큰 출력.
[SAFETY] 조건은 개별 상담과 동일.
```

`[SAFETY]`, `[COOLDOWN]` 같은 제어 토큰은 서버가 파싱해서 실제 UI 분기(세션 분리, 기관 안내 화면)를 실행한다 — **프롬프트가 아니라 시스템이 안전을 보장**하는 구조.

### 품질 확보 방법

- 시나리오 평가셋 구축: 갈등 유형별(가족/친구/직장) 모의 대화 30~50개로 회귀 테스트 (편들기 여부, 절차 이탈, 안전 분기 정확도 채점)
- 초기엔 **개별 상담(1단계)만 출시**하고 합동방은 베타 게이트 — 개별 상담이 훨씬 안전하고, 데이터가 쌓인 뒤 합동방 프롬프트를 조정
- 모델: Claude API (긴 맥락 + 뉘앙스 있는 한국어 존댓말 + 안전성). 프롬프트 캐싱으로 시스템 프롬프트 비용 절감

## 비용·운영 메모

- 개별 상담: 세션당 토큰 예산 상한 설정, 일일 세션 수 제한 (구독 티어 차등)
- 합동방: 실시간성 필요 → 스트리밍 응답, 세션 길이 45분 제한 (실제 조정 실무도 세션제)
- 대화 로그: 암호화 저장, 모델 학습 미사용 명시, 상대방에게는 "공유 동의한 요약"만 전달 (원문 비공개)
