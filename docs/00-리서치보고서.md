## 1. 학술 연구: 심리학이 말해주는 것

### 1-1. "오랜만에 연락하기"의 심리 (앱의 핵심 가설 검증)

✅ **사람들은 오랜 친구에게 연락하는 것을 놀라울 만큼 꺼린다.**
- 대다수가 "연락 끊긴 친구가 있다"고 답했지만 재연락 의향은 낮음
- 연락하고 싶고, 상대가 반가워할 거라 생각해도 **실제로 메시지를 보낸 사람은 1/3 이하** (스터디3: 27.8%, 스터디4: 36.8%)
- 오랜 친구에게 연락하는 심리적 부담 = **낯선 사람에게 말 거는 부담과 통계적으로 동등** (N=288)
- 오래 끊긴 관계일수록 상대가 "낯선 사람처럼" 느껴져 더 꺼림
- 출처: Aknin & Sandstrom (2024), *Communications Psychology* (Nature 계열), 7개 스터디 — https://www.nature.com/articles/s44271-024-00075-8

✅ **"워밍업 연습" 개입이 실행률을 극적으로 높인다.**
- 현재 친한 친구에게 가벼운 메시지를 보내는 **3분짜리 연습**을 먼저 시키면, 오랜 친구에게 실제 연락한 비율이 **31% → 53%** (N=194, p<.001, d=0.46)
- 같은 논문 스터디 7. 사전등록(pre-registered) 예측 적중

✅ **연락받는 쪽은 보내는 쪽 예상보다 더 반가워한다.**
- Liu et al. (2023, JPSP): 수신자의 반가움(M=4.81) > 발신자의 예상(M=4.36), d=0.32
- 더 큰 표본(n=742)의 **독립 재현 연구에서도 성공적으로 재현** (d=0.25)
- 출처: https://replications.clearerthinking.org/replication-2023jpsp124-4/

> **잇다에 주는 시사점 (핵심)**
> 1. 앱이 공략할 심리적 병목이 실재한다: "하고 싶은데 못 보낸다" — 의지 문제가 아니라 **불안 문제**
> 2. 검증된 해법이 존재한다: **낮은 부담의 연습 단계**를 앱 플로우에 그대로 이식 (예: 본 연락 전에 가까운 사람에게 가벼운 안부 보내기 미션)
> 3. "상대는 당신 생각보다 훨씬 반가워해요 (연구 결과 d=0.32)" — **근거 기반 넛지 카피**로 사용 가능

### 1-2. 용서(Forgiveness) 개입 모델

✅ **Worthington의 REACH 모델이 사실상의 표준이다.**
- 5단계: **R**ecall the hurt(상처 직면) → **E**mpathize(가해자 공감) → **A**ltruistic gift(이타적 선물로서의 용서) → **C**ommit(용서 결심 공표) → **H**old on(용서 유지)
- 25편 이상의 RCT로 다수 연구실에서 검증. 대학생 대상 문헌고찰에서 검토된 개입의 40%가 REACH, 40%가 Enright 모델
- 2024년 BMJ Public Health 5개국 트라이얼(N=4,598)도 존재
- 출처: Frontiers in Psychology (2020), Cogent Education (2024) 문헌고찰

✅ **효과 크기가 정량적으로 확립되어 있다.**
- Wade et al. 2014 메타분석(54편, N=2,323): **개입 총 시간이 효과의 주요 예측 변수** (시간당 약 +0.1 SD)
- 6시간 심리교육 기준: 용서 +0.6 SD, 우울·불안 각 +0.3 SD 개선
- 2024 메타분석(RCT 11편): d=.69

✅ **상담자 없는 셀프 워크북 형식도 효과가 확인됐다.**
- 2024 문헌고찰에서 5개 연구가 트레이너 없는 자율 워크북 형식으로 긍정적 결과
- 단, 자율 형식은 시간당 효과가 집단 형식보다 작음 (d/h ≈ 0.15)

> **잇다에 주는 시사점**
> 1. **앱 기반 셀프 가이드 용서 개입은 학술적으로 실현 가능** — 워크북 RCT가 직접 근거
> 2. 콘텐츠 설계는 REACH 5단계를 그대로 프로그램화하면 됨 (검증된 커리큘럼이 공개되어 있음)
> 3. **총 사용 시간이 효과의 핵심 변수** → 짧은 세션을 여러 날에 걸쳐 누적시키는 설계(예: 하루 10분 × 4주)가 근거에 부합
> 4. 주의: 근거의 상당수가 대학생 표본. 중장년·가족 갈등 맥락 일반화에는 한계

### 1-3. 사과(Apology)의 구조

✅ **효과적인 사과의 6요소** (Lewicki, Polin & Lount 2016, N=755)
1. 유감 표명 (I'm sorry)
2. 잘못에 대한 설명
3. **책임 인정** ← 가장 효과적
4. 뉘우침 선언
5. **보상 제안** ← 두 번째로 효과적
6. 용서 요청 ← 가장 덜 중요

> **잇다에 주는 시사점**
> 사과 메시지 작성 가이드를 이 6요소로 구조화. UI에서 "책임 인정"과 "보상 제안"을 필수 블록으로, "용서 요청"은 선택 블록으로. 변명("~했지만")을 감지해 경고하는 기능도 고려.

## 2. 시장: 시중 앱 분석

✅ **Fabriq** (미국) — 관계 리마인더/퍼스널 CRM
- 최대 150명(던바 수)을 서클 단위로 관리, 재연결 목표·반복 알림
- 무료 + 구독 $4.99/월, $39.99/년. 광고·데이터판매 없음 표방
- **2024년 중반 이후 업데이트 정체** → 단독 카테고리로는 사업 지속이 어려웠을 가능성

✅ **인물 - 대인관계 노트** (한국, 슈퍼프린) — 관계 기록 앱
- 인물별 대화·만남 노트, 취향 기록, 후속연락·생일 리마인더, 타임라인, 그룹 분류
- 현재도 활발히 업데이트 중 (v1.66.0)
- **화해·용서 특화 기능은 없음** — 기록/관리형에 머묾

⚠️ **Paired** (커플 관계개선 앱) — 2021년 $3.6M 시드 투자, 월 다운로드 ~9만·월 매출 ~$20만 수준 추정(Sensor Tower), 구독 $4.99/주 또는 $59.99/년, 파트너 무료 초대 모델
⚠️ **퍼스널 CRM 가격대**: Dex $15-20/월, Clay $30+/월(무료 1,000명·LinkedIn/iMessage 연동), Monica는 유일한 오픈소스·셀프호스팅 옵션

**핵심 발견: 화해·용서에 특화된 직접 경쟁 앱은 이번 조사에서 확인되지 않았다.**
- 기존 앱들은 "관계 유지·기록"(퍼스널 CRM) 또는 "현재 관계 개선"(커플 앱)에 집중
- "끊어진 관계의 회복"은 시장 공백 — 단, 이것이 **기회인지 수요 부재인지는 미검증** (MVP로 검증 필요)

> **잇다에 주는 시사점**
> 1. 차별화 포인트가 명확함: 기록·리마인더(경쟁사 존재)가 아니라 **회복 여정(용서 프로그램 + 사과 가이드 + 재연락 용기)**이 잇다만의 것
> 2. 수익모델 벤치마크: 구독 $4.99/월 안팎이 이 카테고리의 가격대. Paired의 "한쪽이 결제하면 상대는 무료" 모델은 화해 시나리오와 궁합이 좋음
> 3. Fabriq의 정체는 경고: 리마인더만으로는 리텐션이 약하다 → 콘텐츠(회복 프로그램)가 본체여야 함

## 3. 데이터 수집 현실성 (냉정한 결론)

✅ **Facebook Graph API — 사실상 폐쇄.**
- `/user/friends`는 전체 친구가 아니라 **"이 앱을 같이 쓰면서 user_friends 권한을 준 친구"만** 반환 (양쪽 동의 필요)
- 신규 앱은 사용자의 친구 중 앱 사용자가 0명 → **빈 목록만 받음**
- 우회 엔드포인트(taggable_friends 등)도 폐기됨. 2014년 v2.0부터 시작된 제한이며 Cambridge Analytica 이후 더 강화
- 출처: Meta 공식 문서 (2026-07-20 라이브 확인)

⚠️ **카카오톡 친구 API — 동일한 구조의 제한.**
- 카카오 공식 문서 기준: 친구 목록 API는 **"앱과 이미 연결되어 있고 친구 목록 제공에 동의한 친구"만** 반환. 별도 권한 신청 필요, 응답 10분 캐시
- 즉 연락 끊긴 친구(= 앱 미사용자)는 카카오 API로 절대 얻을 수 없음 → **잇다의 핵심 시나리오와 정면 충돌**
- 출처: https://developers.kakao.com/docs/latest/ko/kakaotalk-social/common

⚠️ **LinkedIn — 2015년 이후 공개 API 폐쇄.** 파트너 프로그램 승인시에만 제한적 접근. 소규모 신규 앱에게는 실현 불가능한 경로. (링크드인의 "소셜 그래프 오픈소스"는 존재하지 않음 — LinkedIn이 공개한 오픈소스는 Kafka 등 인프라 도구이지 그래프 데이터가 아님)

⚠️ **기기 연락처 — 유일하게 현실적인 경로이나, 정책이 강화되는 중.**
- iOS 18부터 "일부 연락처만 공유(limited access)"가 기본 흐름. 전체 주소록 접근 요구는 사용자 거부감·심사 리스크 큼
- Apple의 권장 패턴: `ContactAccessButton`으로 필요할 때 특정 연락처만 추가 공유 — **"다시 연결할 사람 선택" UX와 정확히 맞는 공식 API**
- Android는 `READ_CONTACTS` 런타임 권한으로 여전히 가능하나 Play 정책상 용도 소명 필요

### 결론: 실현 가능한 데이터 소스 우선순위

| 순위 | 소스 | 실현성 | 비고 |
|---|---|---|---|
| 1 | **사용자 직접 입력** | ◎ | 관계·추억·갈등 맥락은 어차피 API로 못 얻음. 입력 UX를 카테고리 선택형으로 쉽게 |
| 2 | **기기 연락처 (선택적 접근)** | ○ | iOS ContactAccessButton / Android 연락처 선택기. "전체 동기화"가 아니라 "이 사람 불러오기" |
| 3 | 카톡/SNS 친구 API | ✕ | 앱 미사용 친구는 못 얻음 — 설계에서 배제 |
| 4 | LinkedIn | ✕ | 파트너 승인 필요 — 배제 |

> **잇다에 주는 시사점 (설계 원칙 전환)**
> "소셜 그래프를 자동으로 긁어오는 시스템"은 2026년 현재 **불가능하다**. 대신:
> - 관계 그래프는 **사용자가 한 명씩 등록하는 방식**으로 구축 (연락처에서 선택적 불러오기로 마찰 최소화)
> - 이것은 오히려 장점이 될 수 있음: 잇다의 그래프는 "팔로우 관계"가 아니라 **"마음이 쓰이는 관계"만 담긴 고밀도 그래프** — 프라이버시 우려도 원천 차단
> - 연락 실행은 앱 밖(카톡/문자/전화)에서 하도록 유도하고, 앱은 "보낼 메시지 작성 + 용기 부여 + 결과 기록"을 담당 (메시지 앱과 경쟁하지 않음)

> **잇다에 주는 시사점**
> - 개인당 관계 수는 수십~수백 명 수준 → **초기에는 그래프 DB가 필요 없다.** PostgreSQL + 재귀 CTE로 충분
> - 그래프 분석(소개·연결 추천)이 실제로 필요해지는 시점에 Apache 2.0 계열(JanusGraph)이나 Neo4j 도입 검토
> - Monica는 관계 데이터 모델(Contact–Activity–Reminder–LifeEvent) 설계 참고서로만 활용

## 6. 남은 조사 과제 (Open Questions)

1. 카카오톡 메시지 API(피커로 친구 선택해 메시지 보내기)가 "앱 미사용 친구에게 초대장 보내기" 용도로 쓸 수 있는지 실제 심사 기준 확인
2. REACH 기반 **디지털 전달형** 개입의 RCT 존재 여부 (셀프 워크북의 낮은 시간당 효과를 앱 UX로 얼마나 보완 가능한지)
3. "끊어진 관계 회복" 수요의 실측 — 직접 경쟁자 부재가 공백인지 수요 부재인지 (MVP 지표로 검증)
4. B2B(직장 갈등) 시장의 기존 솔루션 조사 — 국내 조직문화 진단 툴, 해외 워크플레이스 미디에이션 서비스 (추가 리서치 필요)
