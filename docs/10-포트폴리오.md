# 10. 포트폴리오 스토리 (면접·자소서용)

> 형식: **상황 → 고민 → 결정 → 근거 → 결과**. 수치 필수. 면접에서 "왜 그렇게 했어요?"에 바로 답할 수 있는 단위로 기록한다.

## 프로젝트 한 줄 요약

**잇다(Itda)** — 끊어진 관계를 다시 잇는 앱. 심리학 연구(RCT·메타분석)를 근거로 "재연락의 심리적 장벽"을 낮추는 개입을 제품화. Spring Boot 4 + React Native(Expo) 풀스택 1인 개발.

## 스토리 카드

### 1. 리서치가 기획을 뒤집다 — "소셜 그래프 자동 수집" 포기

- **상황**: 초기 아이디어는 카톡/페이스북/링크드인에서 친구 관계를 가져와 관계망을 만드는 것.
- **고민**: 정말 가능한가? 경쟁 앱은 어떻게 하나?
- **결정**: 조사 후 **자동 수집 전면 배제**. 사용자 직접 등록 + 연락처 선택 불러오기로 전환.
- **근거**: Meta 공식 문서 검증 — `/user/friends`는 "같은 앱을 쓰며 권한을 준 친구"만 반환(신규 앱엔 빈 목록). 카카오 친구 API도 동일 구조. LinkedIn은 2015년부터 파트너 전용.
- **결과**: 개인정보 리스크 원천 차단 + iOS 18 연락처 정책(limited access)과 자연스럽게 부합하는 설계. **제약 조사가 아키텍처를 결정한 사례.**

### 2. 기능이 아니라 논문에서 출발한 핵심 UX

- **상황**: "연락할 용기를 준다"를 어떻게 기능으로 만들까.
- **고민**: 감성 문구만으로는 근거가 없다.
- **결정**: 검증된 개입을 그대로 제품화 — ① 워밍업 단계(가까운 사람에게 먼저 안부) ② 근거 기반 넛지 카드 ③ 추억 자동 삽입 초안.
- **근거**: Aknin & Sandstrom(2024, Nature Comm. Psychol.) — 워밍업 연습으로 실제 연락률 **31%→53%** (N=194, d=0.46). Liu et al.(2023 JPSP, 독립 재현) — 수신자의 반가움은 발신자 예상보다 높음(d=0.32).
- **결과**: 미션 플로우 4단계가 전부 논문 매핑됨. "이 버튼이 왜 있는가"에 실험 데이터로 답할 수 있는 UX.

### 3. 그래프 DB를 "안 쓴" 결정

- **상황**: 관계망 서비스니까 Neo4j?
- **고민**: 개인당 관계 수는 수십~수백. 조회 패턴은 "내 사람 목록"이 전부.
- **결정**: **PostgreSQL 단일 저장소**, 스키마만 그래프형(person–relationship)으로 설계해 이관 대비.
- **근거**: 규모상 재귀 CTE로 충분. Neo4j CE는 GPLv3 카피레프트 논쟁 + 운영 부담. Monica CRM(AGPL)도 코드 재사용 배제, 데이터 모델만 참고.
- **결과**: 인프라 0개 추가로 MVP 완성. **기술 선택을 트래픽·라이선스·운영 비용으로 정당화한 사례.**

### 4. Spring Boot 4 조기 도입과 마이그레이션 대응

- **상황**: 문서상 계획은 Boot 3.x였으나 로컬 검증 환경은 Boot 4.1.
- **고민**: 안정 버전 고수 vs 최신 체계 학습.
- **결정**: Boot 4.1 채택, 4.x 스타터 체계(`starter-webmvc`, 모듈별 `-test`)와 Jackson 3(`tools.jackson`) 기반으로 작성.
- **결과**: 테스트 11건 전부 신규 체계로 통과. 버전 전환기의 breaking change(MockMvc 자동설정 이동 등)를 직접 경험.

### 5. 도메인 규칙을 엔티티 안에 — 재연락 상태기계

- **상황**: 미션(워밍업→부스터→초안→전송→완료)의 단계 전이를 어디서 관리할까.
- **고민**: 서비스 레이어의 if-else vs 도메인 모델.
- **결정**: `MissionStep.next()` enum 전이 + `Mission.recordResult()`에 결과별 규칙 캡슐화 (REPLIED→완료+마지막 연락일 갱신 / NO_REPLY→열린 채 유지 / NOT_SENT→격려 후 종료).
- **결과**: 컨트롤러·서비스는 얇게 유지, 규칙 변경 시 수정 지점이 엔티티 한 곳. MockMvc 통합 테스트 5건으로 전이 전부 검증.

### 6. 안전을 기능보다 위에 — safety by design

- **상황**: 학대·폭력 관계까지 "재연결"을 부추기면 앱이 해를 끼친다.
- **결정**: 등록 4단계에 안전 스크리닝 → `safetyConcern=true`면 서버가 미션 생성을 **409로 거부**(UI 우회 불가), 상세 화면은 보호 모드(전문기관 안내)로 분기. "용서≠재연결" 원칙으로 '연락 없이 마음 정리' 경로를 동등한 성공으로 취급.
- **결과**: 윤리 요구사항을 프론트 문구가 아니라 **백엔드 불변식**으로 구현. 도메인 테스트로 보장.

### 7. 로컬 개발 환경의 멀티 프로젝트 충돌 해결

- **상황**: 기존 프로젝트(sealo)와 포트 충돌(8080/8081/5432).
- **결정**: 잇다 전용 포트 규칙(8090/8082/5433)을 결정로그로 문서화, compose·설정·클라이언트에 일관 반영.
- **결과**: 두 프로젝트 동시 기동 가능. 사소해 보여도 **환경 문제를 규칙·문서로 해결하는 습관**을 보여주는 사례.

### 8. 리마인더를 서버 푸시 없이

- **상황**: 연락 주기 알림 + 24시간 팔로업이 필요. 서버 푸시는 인프라(Redis, FCM 토큰 관리)가 큼.
- **결정**: MVP는 **기기 로컬 알림**(expo-notifications)으로. 주기 데이터만 서버에 저장, 예약·취소는 클라이언트가 identifier 규칙(`cycle-{id}`, `mission-{id}`)으로 관리.
- **결과**: 인프라 추가 0으로 리마인더 완성. "아직 답 없어요"면 팔로업 유지, 결과 기록 시 자동 취소 같은 세밀한 규칙 포함.

### 9. AI 중재 시스템 설계 (Phase 2 설계 완료)

- **상황**: 갈등 당사자 둘을 바로 한 방에 넣으면 악화될 수 있다.
- **결정**: 전문 조정의 카우커스·셔틀 조정 기법을 본떠 **개별 AI 상담 → 요약 본인 승인 → 왕복 릴레이(3회 제한) → 선택적 합동방** 구조 설계. 안전은 프롬프트가 아니라 시스템이 보장 — AI가 `[SAFETY]`/`[COOLDOWN]` 제어 토큰을 출력하면 서버가 파싱해 실제 분기 실행.
- **결과**: LLM 제품에서 **프롬프트·안전장치·UX를 함께 설계**한 문서(docs/07). 조정 실무 근거 포함.

## 면접 예상 질문 대비

- **"왜 RN이고 Flutter가 아닌가?"** → 국내 채용 시장의 React 수요 + 기존 React 역량 재사용 + 이 앱의 UI 특성(폼·리스트 중심, 고성능 그래픽 불필요).
- **"OSIV를 왜 껐나?"** → 커넥션을 응답 직렬화까지 물고 있으면 트래픽 시 풀 고갈. 명시적 fetch 전략 + `default_batch_fetch_size=100`으로 N+1 완화.
- **"AI를 얼마나 활용했나?"** → 숨기지 말 것. "AI 페어 프로그래밍으로 생산성을 높이되, 아키텍처 결정·검증 기준·윤리 원칙은 직접 정의하고 결정로그로 남겼다"가 2026년 채용 시장에서 오히려 강점. 결정로그 24건이 그 증거.
- **"운영 경험은?"** → 솔직하게: 아직 출시 전. 대신 출시 계획(스토어 심사 대응, 지표 설계 — North Star '다시 이어진 관계 수')을 말할 수 있게 준비.
