# 05. B2B 확장 — 회사 안의 잇다 (Itda for Teams)

> 작성일: 2026-07-20
> 위치: MVP 검증 이후의 확장 트랙. 단, 데이터 모델·엔진은 처음부터 B2B를 염두에 두고 설계한다.

## 왜 회사인가

- 직장은 갈등이 가장 자주, 구조적으로 발생하는 공간 (세대 차이, 부서 이기주의, 평가·업무 분배 갈등)
- 개인은 화해 앱에 돈을 잘 안 쓸 수 있지만, **회사는 갈등 비용(이직·저성과·괴롭힘 리스크)에 지불 의사가 있다**
- B2C에서 검증한 동일 엔진(사과 6요소, REACH 화해 프로그램, 재연락/대화 용기 플로우)을 직장 맥락으로 포팅 가능

## 제품 형태

**개인 앱과 분리된 "워크스페이스 모드"** (같은 앱 내 조직 코드 입장 or 별도 앱 — 결정 보류, [03-결정로그](03-결정로그.md))

### 모듈 1: 셀프 갈등 코칭 (개인용, 익명)
- 직장 갈등 상황 기록 + 감정 정리 저널
- REACH 기반 "직장 버전" 프로그램: 동료에 대한 원망 정리, 관점 전환(상대 입장 공감) 훈련
- 어려운 대화 준비 도우미: 비폭력 대화(NVC) 구조로 할 말 정리 — "관찰-감정-욕구-요청"
- 사과 작성 가이드 (6요소, 직장 톤)

### 모듈 2: 1:1 화해 브리지 (양자 동의 기반)
- A가 B에게 "대화 요청" 발송 (수락 전에는 내용 비공개)
- 양쪽이 각자 앱에서 사전 워크시트 작성 (내 관점 / 상대 관점 추측 / 원하는 것)
- 구조화된 대화 가이드와 함께 오프라인 1:1 미팅 안내
- 사후 체크인 (1주 후 "관계가 나아졌나요?")
- **강제 배정 금지**: HR이 두 사람을 지정해 강제로 화해시키는 기능은 만들지 않는다 (강요된 화해는 역효과 + 윤리 위반)

### 모듈 3: 조직 리포트 (관리자용, 익명 집계만)
- 팀 단위 갈등 온도(익명 펄스 설문), 프로그램 이용률, 화해 브리지 성사율
- **개인 식별 불가**: 최소 N명(예: 8명) 이상 집계만 노출, 개인 기록·대화 내용은 회사가 절대 열람 불가
- 이것이 신뢰의 전부다 — 직원이 "회사가 본다"고 의심하는 순간 제품은 죽는다

## 신뢰 아키텍처 (설계 원칙)

1. 개인 기록은 개인 계정 소유. 회사 관리자 권한으로 접근 불가 (기술적으로 분리: 조직 스키마에서 개인 콘텐츠 테이블 참조 금지)
2. 익명 집계 최소 인원 미달 시 리포트 자체를 숨김
3. 퇴사·탈퇴 시 개인 데이터는 개인이 가져가거나 삭제
4. 직장 내 괴롭힘 신호 감지 시: 화해 유도 대신 **신고 채널·노무 전문기관 안내로 분기** (괴롭힘은 "화해"의 대상이 아니라 보호의 대상)

## 경쟁 환경 (추가 조사 필요 — [00-리서치보고서](00-리서치보고서.md) §6)

- 국내: 조직문화 진단·펄스 설문 툴은 존재하나, **갈등 당사자 간 화해 프로세스**를 제공하는 제품은 미확인
- 해외: 워크플레이스 미디에이션은 대부분 사람(외부 조정가) 서비스 — 소프트웨어화된 직접 경쟁자 조사 필요

## 수익 모델 (가설)

- 인당 월 과금 (팀 단위 최소 계약)
- 파일럿: 스타트업·중소기업 HR 대상 무료 파일럿 → 사례 확보 → 중견·대기업 영업

## B2C 엔진과의 공유/분리

| 구성요소 | 공유 여부 |
|---|---|
| 사과 6요소 에디터, REACH 프로그램 엔진, 대화 준비 도우미 | ✅ 공유 (콘텐츠 팩만 직장 버전) |
| 관계 모델 (person/relationship) | ✅ 공유 |
| 조직/멤버/익명 집계 도메인 | 🆕 B2B 전용 |
| 추억 기록, 재연락 미션 | B2C 전용 (직장 맥락에선 축소) |
