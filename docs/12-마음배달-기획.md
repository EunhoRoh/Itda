# 12. 마음 배달 (가칭) — 사용자 간 감정 메시지 전달 + AI 재작성

> 작성일: 2026-08-05 · 출처: 사용자 브레인스토밍 전문 분석
> 상태: **기획 검토** — 핵심 구조는 제안 확정 대기, 리서치 검증 결과는 §11
> 원칙: 사용자 아이디어를 항목별로 **채택 ✅ / 수정 채택 🔧 / 기각 ⛔** + 근거로 분석한다. 하나도 빠뜨리지 않는다.

## 0. 한 줄 정의와 위치

**사용자 A가 사용자 B에게 감정(고마움·호감·사과·화해 의향…)을 전하면, AI가 다듬어 배달하고, 양쪽이 원할 때만 대화로 이어지는 기능.**

기존 잇다와의 관계 — 잇다의 **두 번째 엔진**이다:
- 엔진 1 (기존): "내가 용기 내서 **직접** 연락" — 앱은 조력자, 전송은 카톡/문자로, 상대가 앱 사용자일 필요 없음
- 엔진 2 (신규): "앱이 **대신** 배달" — 사용자↔사용자, 네트워크 효과 발생, 회원/인증 선행 필요

→ 별개 기능이 아니라 같은 미션("감정을 전하기 쉽게 → 관계를 잇는다")의 다른 전달 경로. 두 엔진은 릴레이 중재(docs/07)로 합류한다.

## 1. 익명 발신 — 핵심 구조 제안 🔧 (원안에서 가장 중요한 수정)

### 원안
누군가 나에게 서운했던 점·불편함·화남·증오까지 익명으로 보낼 수 있고, AI가 다듬어 전달한다.

### 분석 — 익명 × 감정 방향의 매트릭스

|  | 긍정·회복 지향 (고마움/호감/사과/화해·오해풀기 의향) | 부정 감정 그 자체 (화남/증오/시기/질투/슬픔 통보) |
|---|---|---|
| **익명** | ✅ 작동함 — Gas 앱(익명 칭찬)이 증명한 모델. 받는 쪽 부담 낮고 기분 좋음 | ⛔ **금지 권고** — Sarahah·NGL·Yik Yak이 실패한 바로 그 패턴 |
| **실명** | ✅ 허용 (직접 작성 + 선택적 AI 다듬기) | 🔧 단방향 통보 대신 **릴레이 중재 초대로 변환** |

**익명 부정 통보를 막아야 하는 이유 (냉정하게):**
1. **수신자가 할 수 있는 게 없다.** "익명의 누군가가 당신에게 증오를 느끼고 있습니다"를 받으면 해명도 사과도 대화도 불가능 — 남는 건 불안과 "누구지?" 반추뿐. 우리 목적(갈등 해소·연결)에 정확히 반대로 작동한다.
2. **익명이 사실상 깨진다.** 관계 앱 특성상 수신자의 관계망은 좁다. "요즘 나한테 서운할 사람이 누구지?" → 특정 시도 → 엉뚱한 사람을 의심하면 **새 갈등을 만들고**, 맞게 특정하면 익명 약속이 무의미해진다.
3. **괴롭힘 도구화.** 익명+부정은 사이버불링의 표준 레시피다 (Sarahah는 괴롭힘 신고로 스토어에서 퇴출, Yik Yak은 학교들이 차단). 사용자가 직접 물었듯 **스토킹·위험 요소가 실재한다** — 하루 3명 제한으로는 못 막는다(계정당 3명씩 반복 가능).
4. AI가 아무리 잘 다듬어도 "익명의 누군가가 화났다"는 **사실 자체**가 위협이다. 문장이 부드러워져도 정보의 본질이 바뀌지 않는다.

**대신 — 부정 감정의 올바른 출구 (이미 우리에게 있다):**
서운함·화남은 삭제하는 게 아니라 **릴레이 중재(docs/07)로 라우팅**한다.
- 발신자가 부정 감정을 선택하면 → "이 마음은 일방 전달보다 대화로 풀 때 풀려요" → 개별 AI 상담 → 요약 승인 → 상대에게는 **"OO님이(또는 익명의 누군가가) 당신과 오해를 풀고 싶어 합니다"**로 도착 (감정 통보가 아니라 **대화 의향**으로 변환)
- 수신자는 수락/거절/시간 필요를 선택 — 통보가 아니라 초대이므로 부담이 다르다
- 이러면 사용자가 말한 "욕설·심한 말도 AI가 정리해서 잘 전달"이 안전하게 성립한다: AI가 증오문을 다듬어 *배달*하는 게 아니라, 증오문을 상담에서 받아내고 **정제된 대화 요청**만 밖으로 나간다

> 요약: **익명 = 긍정·회복 지향 전용. 부정 감정 = 중재 경로 전용(익명 여부 무관).** 이것이 이 기획을 "실패한 익명 앱"이 아니라 "잇다"로 만드는 한 끗이다.

## 2. 선택지 문구 12종 평가 (사용자 원문 그대로 검토)

| 원안 문구 | 평가 | 처리 |
|---|---|---|
| 익명의 누군가가 당신과 **화해를 하고 싶습니다** | 잘 씀 — 대화 의향형 | ✅ 채택 |
| ~ 당신께 **용서를 구하고 싶습니다** | 잘 씀 — 낮은 자세, 수신자 우위 | ✅ 채택 |
| ~ 당신과 **오해를 풀고 싶습니다** | 잘 씀 — 가장 중립적, 부정 감정의 변환 착지점 | ✅ 채택 (부정 라우팅의 기본 문구) |
| ~ 당신에게 **화가 났습니다** | 통보형 — 수신자가 할 수 있는 게 없음 | ⛔ 익명 금지 → 중재 초대로 변환 |
| ~ 당신 때문에 **슬퍼하고 있습니다** | 죄책감 유발형 ("때문에") — 원칙 위배 | ⛔ 동일 변환 |
| ~ 당신으로 인해 **증오를 느끼고 있습니다** | 위협으로 수신됨 — 신고 사유 수준 | ⛔ 발신 자체 차단 + 발신자에게 마음 정리 경로 안내 |
| ~ 당신에게 **시기심을** / **질투심을** 느끼고 있습니다 | 수신자에게 정보 가치 없음, 불안만 | ⛔ 발신자 셀프 저널로 흡수 |
| ~ 당신에게 **부러움을** 느끼고 있습니다 | 경계선 — "당신이 멋져 보여요"로 재구성하면 긍정 | 🔧 "당신을 닮고 싶어 합니다"로 순화 채택 |
| ~ 당신에게 **고마움을** 느끼고 있습니다 | 핵심 긍정 | ✅ 채택 |
| ~ 당신에게 **호감을** 느끼고 있습니다 | 긍정, 단 로맨틱 맥락은 상호 공개 장치 필요(§6) | ✅ 채택 (+mutual 장치) |
| ~ 당신에게 **사랑을** 느끼고 있습니다 | "사랑"은 익명일 때 부담·공포 반반 | 🔧 "당신을 오래 마음에 담아두고 있습니다"로 순화, mutual 장치 필수 |

**추가 제안 문구 (요청하신 확장):**
- ~ 당신에게 **미안한 마음을 오래 갖고 있습니다** (사과 진입)
- ~ 당신과의 **추억을 소중히 간직하고 있습니다** (재연결 진입, 옛 인연용)
- ~ 당신의 **안부를 궁금해합니다** (가장 가벼운 진입)
- ~ 당신에게 **응원을 보내고 싶어 합니다** (힘든 시기 지지)
- ~ 당신 덕분에 **힘든 시기를 지나왔습니다** (감사 심화형)

## 3. AI 재작성 파이프라인 ✅ (원안 채택 + 정밀화)

원안: 익명이면 본인 작성 원문 전송 불가, AI 재작성 3회 중 택1 또는 준비 문구만. 실명이면 직접 작성/선택지/AI 수정 모두 가능.

**평가: 구조가 정확하다. 채택.** 근거는 AI 중재 커뮤니케이션 연구(§11) — AI가 재구성한 표현이 대화 질과 수용도를 높인다는 실험 증거가 있다.

파이프라인:
```
[발신자 원문] → ① 안전 필터 (위협·협박·자해 → 발신 차단 + 발신자 케어 분기, [SAFETY] 토큰 체계 재사용)
             → ② 신원 정보 제거 (익명일 때: 이름·별명·장소·특정 사건 등 발신자를 특정할 단서 마스킹)
             → ③ 감정 구조화 (원문에서 감정·이유·바람 추출 — NVC의 관찰/감정/욕구)
             → ④ 재작성 3안 생성 (톤 다르게: 담백/따뜻/정중) → 발신자가 1개 선택 or 준비 문구로 대체
             → ⑤ 수신자 카드로 배달 (감정 키워드 + AI 재작성 본문 + "AI가 다듬은 메시지예요" 고지)
```
- ⑤의 고지는 필수 — AI 재작성 사실을 숨기면 나중에 알았을 때 진정성 불신이 생긴다(연구 근거 §11). "보낸 이의 마음을 AI가 정리했어요"로 투명하게.
- 3회 제한 + 4회부터 유료: ✅ 채택 (§9 수익화)
- 실명 발신의 직접 작성 허용: ✅ 채택 — 단 발신 전 안전 필터는 실명에도 동일 적용 (욕설·위협은 실명이어도 배달하지 않고 수정 제안)

## 4. 감정별 메시지 양식 ✅ (요청: "각 감정별 양식을 작성해줘야 할까?" → 그렇다)

AI 재작성의 뼈대이자 실명 작성자의 템플릿. 근거 프레임 명시:

| 감정 | 양식 (AI가 채우는 틀) | 근거 프레임 |
|---|---|---|
| 고마움 | "당신이 {구체적 행동}해 주었을 때 → 나에게 {영향}이었다 → 지금도 {마음}" | 감사 표현 연구 — 구체성이 효과의 핵심 |
| 사과 | "{잘못 인정} → {설명(변명 아님)} → {뉘우침} → {보상 의향}" — 용서 요청은 넣지 않음 | Lewicki 6요소 (docs/00 §1-3) |
| 오해 풀기 | "{사건}에 대해 서로 다르게 기억하는 것 같다 → 내 기억은 {관찰} → 당신 이야기를 듣고 싶다" | NVC 관찰/해석 분리 |
| 서운함(중재 경로) | "{관찰}했을 때 → 나는 {감정}을 느꼈다 → 내게 {욕구}가 중요했기 때문 → {요청}" | NVC I-message |
| 호감 | "{함께한 기억/인상} → 그때 {느낌} → 부담 갖지 않길 바란다" — 요구·기대 문장 금지 | 부담 최소화 원칙 |
| 안부/응원 | "{시점}의 당신을 기억한다 → 잘 지내길 바란다" — 답장 요구 없음 명시 | reaching out 연구 (docs/00 §1-1) |

## 5. 익명 닉네임·발신 한도·감정 키워드

- **'용감한 사자' 형용사+동물 조합**: ✅ 채택. 위협감을 낮추고 톤을 데워준다. 규칙 2개 추가 — ① 같은 수신자에게는 같은 닉네임 유지(후속 대화의 연속성) ② 닉네임은 수신자별로 다르게 부여(여러 수신자의 대조로 발신자 특정 방지)
- **하루 3명 제한**: ✅ 채택 (스팸 방지 + 희소성 = 한 통의 무게). 추가 — **같은 수신자에게 주 1회 쿨다운** (수락 전 반복 발신은 스토킹 벡터, 사용자가 직접 우려한 지점의 실질 방어)
- **감정 키워드**: ✅ 좋은 생각. 기존 EmotionTag(그리움/고마움/미안함/즐거움/아쉬움)를 확장해 메시지 카드의 뱃지·수신함 필터·통계("이번 달 고마움 3통")로 사용. AI 필터링 후 "이러이러한 상황이야, 얘기 나눠볼래?" 요약도 이 키워드가 헤더가 된다.

## 6. 수신 UX — 게시판? 채팅? (요청: "UI를 어떻게 구성?")

**제안: 카드 인박스("마음함") → 수락 시에만 대화로 승격.** 카톡식 채팅방도, 공개 게시판도 아니다.

```
[푸시] "새로운 마음이 도착했어요 🧵" (내용 미리보기 없음 — 프라이버시)
  ↓
[마음함] 카드 목록 — 감정 키워드 뱃지 + 발신자(실명 or 용감한 사자) + 도착일
  ↓ 카드 열람
[카드 상세] AI가 다듬은 본문 + 반응 선택:
   ① 마음만 받을게요 (가벼운 리액션 — 발신자에게 "전해졌어요" 알림, 여기서 종료 가능)
   ② 더 얘기하고 싶어요 → 발신자 동의 확인 → 앱 내 대화방 (연락처 비공개)
   ③ 이런 메시지 받고 싶지 않아요 (차단 — 해당 발신자의 재발신 영구 차단, 무료)
  ↓ ②에서 대화가 무르익으면
[연락처 교환 제안] 양쪽이 각각 명시 동의했을 때만 교환 (자동 공개 절대 없음)
```

- **수락 게이트**: 사용자 질문("받은 사람이 수락하게 해야 하나?") → **그렇다.** 모든 전환(열람→대화→연락처)이 수신자 동의 단계다. "부담스럽지 않게"의 구현이 바로 이 단계적 동의다.
- **감정별 UI 톤**: ✅ 채택하되 절제 — 카드의 색·아이콘만 분기(고마움=코랄 웜톤, 화해·오해=딥그린 차분, 호감=피치). 화면 전체를 바꾸면 산만하고, 부정 계열은 어차피 중재 경로라 "진지한 UI"는 중재 화면이 담당.
- **게시판이 아닌 이유**: 게시판은 "쌓인 것을 관리"하는 모델이고, 마음은 한 통씩 열어보는 편지 모델이 정서에 맞다. 기존 잇다 카드 문법과도 일치.

## 7. 릴레이 중재와의 연결 ✅ (요청: "왕복 릴레이 활용할 수 있을까?")

정확히 맞물린다. 마음 배달은 릴레이의 **관문**이 된다:
- 부정 감정 발신 → 곧장 릴레이 개별 상담으로 (§1)
- 긍정 메시지에서 "더 얘기하고 싶어요" → 일반 대화 or (갈등 맥락이면) 릴레이 모드 선택
- 릴레이의 초대장(결정로그 #23, 본인이 직접 전송)은 **비사용자용** / 마음 배달은 **사용자 간** — 두 진입로가 같은 중재 엔진으로 합류

## 8. 옛 인연·짝사랑 (요청: "이전 인연 찾기, 과거 호감 이성에게 용기")

✅ 이 기능의 가장 아름다운 사용 사례이자 가장 위험한 사용 사례 — **상호 공개(mutual reveal)** 장치로 해결:
- 호감·사랑 계열 익명 메시지는 신원을 끝까지 밝히지 않고, **수신자도 발신 후보에게 호감을 표시했을 때만 서로 공개** (Facebook Secret Crush·대학가 Marriage Pact 모델)
- 일방은 영원히 익명 → 거절의 어색함이 없고, 쌍방이면 축하와 함께 공개 → "부담스럽지 않게"의 최적해
- **"나의 소식 전하기"** (요청: "부담 없이 내 소식도 전하고") → 이건 별개 기능이 맞다: 근황 카드(결혼·이직·이사 등)를 내 사람들에게 발행하는 기능. 백로그에 별도 등재 (마음 배달과 구분 — 감정 전달이 아니라 정보 공유)

## 9. 비사용자 도달 (요청: "앱 안 쓰는 사람에게는 문자? 피싱으로 오해? 어떻게 끌어들이지?")

**냉정한 결론: 비사용자에게 익명 메시지는 보내지 않는다.** ⛔
1. 사용자 예상이 정확하다 — 모르는 번호로 "당신과 화해하고 싶습니다" 문자는 피싱·스팸으로 읽히고 차단된다. 앱 링크 포함 시 더더욱.
2. 법적으로도 위험 경계: 원치 않는 반복 메시지는 스토킹처벌법 리스크, 발신번호·광고성 정보 규제(정보통신망법)도 걸린다. 익명 발신 대행은 서비스가 책임을 진다.
3. **익명의 전제는 "받는 쪽도 규칙에 동의했다"는 것.** 앱에 가입한 사람만 익명 카드를 받는 규칙에 동의한 상태다. 비동의자에게 익명은 그냥 발신번호 숨긴 문자다.

**비사용자 경로는 이미 있다 (일관성):** 결정로그 #23 — 앱이 문구+링크를 만들고 **본인이 실명으로, 본인의 카톡/문자로 직접** 보낸다. "지수야, 나 민준이야. 너한테 전하고 싶은 마음이 있어서 여기 남겼어 [링크]" — 아는 사람의 실명 문자는 피싱으로 읽히지 않는다. 수신자는 링크에서 **가입 없이 게스트로 열람**(결정로그 #24) → 열람 경험이 좋으면 가입 → 이게 성장 루프다.
- 카카오톡 채널: 채널 추가를 시켜야 도달 가능(마찰 큼) + 알림톡은 정보성 제한 → 백로그(우선순위 낮음)
- SMS로 시작?: 위 이유로 익명 SMS는 하지 않는다. 실명 직접 전송만.

## 10. 학교·회사 (요청: "학교와 회사에서 유용할 것 같다, 사춘기 아이들에게 도움")

- **회사**: ✅ B2B(docs/05)와 자연 통합 — 익명 감사·칭찬 전용("동료의 감사가 도착했어요")은 조직문화 도구로 검증된 모델. 부정은 기존 설계대로 중재·신고 채널로. 마음 배달의 콘텐츠 팩만 직장 톤으로.

## 15. 추가 아이디어 분석 (2026-08-06 새벽 브레인스토밍)

### 15-1. 커넥트 플로우 — 수신자가 발신자를 추정했을 때 ✅ 채택 (정밀화)

원안: 받은 사람이 발신자를 추정하면 '커넥트' → 발신자가 알림을 받고 실명 공개 여부를 결정.

**채택.** §6의 수락 게이트를 발신자 쪽 동의까지 완성하는 설계다 — **공개 결정권은 항상 발신자에게**:

```
수신자: 카드 열람 → [커넥트 — 더 얘기하고 싶어요]
  ↓ (수신자의 추측이 맞는지 여부는 시스템이 확인해주지 않는다 — "OO지?" 답 안 함)
발신자 알림: "상대가 대화를 원해요" → 3택:
  ① 실명 공개하고 대화     → 실명 대화방 (+ 선택: AI 동석)
  ② 익명 유지한 채 대화    → 닉네임('용감한 사자') 대화방, AI 동석 기본
  ③ 아직은 마음만 전할게요  → 수신자에게 "마음만 남기고 싶어 해요" 완곡 전달, 종료
```
- 중요 규칙: 수신자가 "혹시 지훈이야?"라고 물어도 **시스템은 긍정도 부정도 하지 않는다**. 확인해주는 순간 소거법으로 익명이 깨진다. 공개는 오직 발신자의 ①번 선택으로만.

### 15-2. 익명 상태로 "무슨 일이 있었는지" 나누기 ✅ 채택

원안: 익명으로 하면 서로에게 어떤 일이 있었는지 나누게 하기.

**채택 — 이것이 15-1 ②번 방의 정체다.** 익명 대화방은 자유 채팅이 아니라 **구조화된 나눔**(릴레이 lite): AI가 "그때 각자에게 어떤 일이 있었는지" 순서대로 묻고 정리한다. 신원 단서(이름·장소·특정 사건)는 AI가 마스킹을 유지. 서로의 사정을 알게 된 뒤 발신자가 원하면 ①(실명 공개)로 승격.

### 15-3. "진전 없으면 접되, 앱이 계속 용서해보라고·용기 내라고 알림" 🔧 수정 채택 (원안의 '계속'은 위험)

**여기는 솔직하게 반대 지점입니다.** "계속 용서해보라"는 반복 알림은 잇다의 제1원칙과 정면 충돌합니다 — 화해 강요 금지, 죄책감 유발 카피 금지(결정로그 #12, docs/01 윤리), "연락 없이 마음 정리도 동등한 성공". 용서를 재촉하는 앱은 상처를 다루는 앱이 될 수 없고, 수신 알림이 잦아지는 순간 이 기능 전체가 스팸이 됩니다.

**수정안 — 넛지는 1회·옵트인·본인 발의로:**
- 대화를 접을 때 3택: 「완전히 마무리」 / 「마음 정리 프로그램으로」 / 「**30일 후 한 번만 다시 물어봐줘**」
- 세 번째를 본인이 고른 경우에만, 30일 후 **1회** 체크인: "그때 접어둔 마음, 지금은 어떤가요?" — 용서 권유가 아니라 상태 질문. 무응답이면 그걸로 끝, 재알림 없음.
- "오해가 있는 건 아닐까요?" 같은 관점 제안은 알림이 아니라 **본인이 열어본 화면 안에서만** 노출.

### 15-4. 실명 공개 후 AI가 채팅에 동석해 중재 ✅ 채택

원안 그대로 채택 — 이미 설계된 실시간 합동방(docs/07 v2)의 안전장치(발언 정리·리프레이밍·개입→냉각→종료)를 재사용한다. 명칭 **"AI 동석 모드"**: 익명 대화방은 기본 켜짐, 실명 대화방은 양측 동의로 켜고 언제든 끌 수 있음(둘만의 대화 존중).

### 15-5. 애프터케어 — 이어진 관계의 주기적 회상 알림 ✅ 채택 (기존 자산과 바로 연결)

원안: 인연이 이어진 후 몇 달·몇 년 후에도 "서로의 추억은 뭐예요?", "당신에게 그 사람은 어떤 사람인가요?" 주기 알림으로 관계를 이어가게.

**채택 — 잇다의 리텐션 루프를 완성하는 조각.** 이미 있는 부품으로 조립 가능:
- 연락 주기 리마인더(구현됨) + 회상 질문 풀(구현됨, 14종) + 미션 결과 기록(구현됨)
- 신규: 재연결(REPLIED→CONNECTED) 시점 기록 → **애프터케어 스케줄** 발동: 1주("첫 연락 후 어떠셨어요?") → 1개월(회상 질문 1개) → 기념일(재연결 1주년 "다시 이어진 지 1년이에요")
- 알림 탭 → 추억 기록 화면 or 가벼운 안부 미션으로 연결 → 기록이 쌓이면 다음 대화의 재료가 되는 선순환
- 원칙 유지: 애프터케어도 설정에서 끌 수 있고, 무응답 2회면 빈도 자동 하향(§15-3과 같은 절제)
