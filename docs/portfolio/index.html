04 기술 의사결정 — 고민의 흔적

모든 결정은 결정로그(24건)에 근거와 함께 기록했고, 번복된 결정도 지우지 않았습니다. 대표 6건:

소셜 그래프 자동 수집을 버렸다

Meta·카카오 친구 API가 "같은 앱을 쓰는 친구"만 반환함을 공식 문서로 검증. 신규 앱엔 빈 목록 → 연락처 선택 불러오기 + 직접 등록으로 전환. 제약 조사가 아키텍처를 결정한 사례.

그래프 DB를 안 썼다

개인당 관계 수십~수백 명 → 재귀 CTE로 충분. Neo4j CE의 GPLv3 논쟁과 운영 비용까지 계산. 스키마만 그래프형으로 두어 이관 비용을 미리 낮춤.

미션을 상태기계로

단계 전이를 enum과 엔티티에 캡슐화(MissionStep.next, recordResult). 결과별 규칙 — 답장 오면 마지막 연락일 갱신, 무응답이면 열린 채 유지 — 을 도메인이 소유. 통합 테스트로 전이 전부 검증.

윤리를 서버 불변식으로

안전 스크리닝에 걸린 관계는 서버가 미션 생성을 409로 거부 — UI를 우회해도 뚫리지 않는다. '용서≠재연결' 원칙으로 연락 없는 마음 정리도 동등한 성공 경로로 설계.

메신저를 만들지 않았다

전송 버튼이 없다. 앱은 '보내기 전(용기·초안)'과 '보낸 후(기록·여정)'만 담당하고 전송은 카톡/문자로. 메신저와 경쟁하지 않는 포지셔닝이자 심리적 자기결정감 보존.

리마인더를 서버 푸시 없이

MVP 단계에서 FCM·Redis 인프라 대신 기기 로컬 알림 채택. identifier 규칙으로 예약·취소 관리 ("아직 답 없어요"면 24h 팔로업 유지). 인프라 0개 추가로 기능 완성.

06 다음 단계 — AI 릴레이 중재 (설계 완료)
