# 잇다 (Itda) 🧵

> **끊어진 관계를 다시 잇는 앱.** 오래 연락 못 한 사람에게 연락할 용기를 주고, 틀어진 관계에는 검증된 심리학 프로그램(용서·사과·화해)으로 회복 여정을 안내합니다.

`Spring Boot 4.1` `Java 21` `React Native (Expo SDK 57)` `TypeScript` `PostgreSQL` `Claude API(설계)`

**📄 포트폴리오 원페이지: [docs/portfolio/index.html](docs/portfolio/index.html)** · 의사결정 스토리: [docs/10-포트폴리오.md](docs/10-포트폴리오.md)

## 왜 만들었나 — 근거 있는 문제 정의

이 프로젝트는 기능 아이디어가 아니라 **검증된 심리학 연구**에서 출발했습니다. (딥 리서치: 24개 소스 → 109개 클레임 → 3인 교차 검증 24건 확정, [리서치 보고서](docs/00-리서치보고서.md))

| 연구가 말해주는 것 | 잇다의 답 |
|---|---|
| 사람들은 옛 친구에게 연락하는 걸 낯선 사람에게 말 걸기만큼 꺼린다 — 실제로 보내는 사람은 1/3 이하 | 의지가 아니라 **불안**의 문제 → 앱이 개입할 지점 |
| 3분 워밍업 연습만으로 실제 연락률 **31% → 53%** (Aknin & Sandstrom 2024, d=0.46) | 미션 1단계 = 워밍업 |
| 연락받는 쪽은 보내는 쪽 예상보다 **더 반가워한다** (Liu et al. 2023 JPSP, 독립 재현 d=0.25~0.32) | 근거 기반 넛지 카드 |
| REACH 용서 모델 — 25편+ RCT, 셀프 워크북 형식도 유효 | Phase 2 회복 프로그램 |

## 핵심 기능 (구현 완료)

- **오늘의 한 사람** — 멀어진 관계 중 가장 오래 끊긴 1명만 추천 (선택 마비 방지)
- **재연락 미션** — 워밍업 → 용기 부스터(연구 넛지 + 추억 카드) → 초안 작성(추억 자동 삽입 템플릿 3종) → 결과 기록. **전송 버튼은 없음** — 복사 후 카톡/문자로, 보내는 순간은 사용자의 것
- **추억 기록** — 전부 탭 선택형(카테고리 9종·감정 태그·연도), 재연락 첫 마디의 재료가 됨
- **안전 설계** — 등록 시 안전 스크리닝, 위험 관계는 서버가 미션 생성을 409로 거부(보호 모드 분기)
- **리마인더** — 관계별 연락 주기 알림 + 미션 24시간 팔로업 (로컬 알림, 서버 푸시 인프라 없이)
- **연락처 불러오기** — 시스템 피커로 1명씩만. 전체 주소록 접근·권한 요청 없음

Phase 2 설계 완료: [AI 릴레이 중재](docs/07-AI중재-설계.md) — 개별 AI 상담 → 요약 본인 승인 → 왕복 릴레이(3회 제한) → 선택적 합동방. 안전은 프롬프트가 아닌 시스템 분기([SAFETY]/[COOLDOWN] 제어 토큰)로 보장.

## 아키텍처

```
┌─ mobile (React Native · Expo SDK 57 · TS) ─────────────┐
│  expo-router  Stack + (tabs)                            │
│  홈 / 사람들 / 나 · 미션 · 등록 · 추억 · 상세             │
│  로컬 알림(expo-notifications) · 연락처 피커              │
└───────────────┬────────────────────────────────────────┘
                │ REST (fetch)
┌───────────────▼─ backend (Spring Boot 4.1 · Java 21) ──┐
│  Controller → Service → Repository (도메인 중심)         │
│  person ── memory                                       │
│     └───── mission (상태기계: WARMUP→…→DONE)             │
│  안전 불변식: safetyConcern → 미션 생성 409               │
└───────────────┬────────────────────────────────────────┘
                │ JPA (OSIV off, batch fetch 100)
        PostgreSQL 16 (docker compose, 5433)
```

## 대표 기술 의사결정 ([결정로그](docs/03-결정로그.md) 24건 중)

1. **소셜 그래프 자동 수집 배제** — Meta/카카오 API는 "같은 앱 사용자"만 반환함을 공식 문서로 검증 → 연락처 선택 불러오기로 전환. 제약 조사가 아키텍처를 결정
2. **그래프 DB 대신 PostgreSQL** — 개인당 관계 수십~수백 명 규모엔 재귀 CTE로 충분. Neo4j CE 라이선스(GPLv3)·운영 비용까지 계산한 선택
3. **도메인 규칙의 위치** — 미션 전이·결과 규칙을 엔티티에 캡슐화, 통합 테스트로 전이 전부 검증
4. **윤리를 백엔드 불변식으로** — "화해 강요 금지, 안전 우선"을 문구가 아니라 서버 규칙으로 구현

## 실행

```bash
# backend (포트 8090)
cd backend && docker compose up -d && ./gradlew bootRun

# mobile (포트 8082, w=웹 미리보기)
cd mobile && npm install && npx expo start --port 8082
```

검증: `cd backend && ./gradlew build` (통합 테스트 11건, H2라 Docker 불필요) · `cd mobile && npx tsc --noEmit`
